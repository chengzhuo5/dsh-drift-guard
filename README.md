# Drift Guard

一个零依赖的 Host 插件，治两个同源的失败模式——**agent 悄悄把"被要求的东西"换成"眼下更方便的东西"**：

1. **跑偏**：会话从一个明确请求开始，遇到问题后悄悄把目标换成"眼下正在修的那件事"。
2. **缩水**：交出一个贴着标签的子集就宣称完成——"最小版本"、"后续再做"。运行时同样察觉不到，因为**缺少的那部分从来没被写成"欠着的东西"**。

## 四种机制

| 机制 | 作用 |
|---|---|
| **基线** | 启动当前请求的人类消息，折进 session projection：随 resume/fork 存活、压缩吃不掉、agent 改不了，且**每次请求重新陈述** |
| **契约** | objective / done_when / **must_deliver** / must_preserve / out_of_scope / main_paths / user_decisions / open_direction_decisions |
| **方向变更协议** | 九类方向级变更必须上报，只有用户能批准 |
| **完整性账本** | 每个 must_deliver 项都要有覆盖判定；未完成项**阻止 turn 以自信的口吻关闭** |

其余一切都是**建议性**的（只丰富下一次请求，不否决调用），所以不会把正常工作的会话锁死。

## 一切按「请求」作用域（真实运行抓出来的核心修正）

第一版把这些绑在了**会话**上，真实运行立刻暴露三个 bug：

| Bug | 现象 | 修正 |
|---|---|---|
| 契约跨 turn 累积 | 新请求配着三轮前的旧契约（revision 已到 4） | 契约绑定 `turnKey`（=启动本请求的人类消息 seq）；旧契约进 `contractHistory`，只作上下文、永不执法 |
| 预算按会话步数算 | `64 used / budget 15`，永远超支 → 每轮都发 checkpoint | 预算改用 `stepsThisTurn`（本请求内闭环步数） |
| 推迟措辞误报 | 报了 6 个标记，全来自"讨论机制"的文本 | 只认**明确宣告**的措辞，且要求同句出现工作动词；只读 `source.kind === 'model'` 的 assistant 记录 |

**为什么是"请求"而不是"turn"**：一个 turn 里可能有多次注入（守卫自己的提醒、question 的回答），它们不应各自重置预算；而**人类消息**才是新请求的边界。所以 `turnKey` 取人类消息的 seq。

## 完整性机制（核心一层）

**声明**：`drift_anchor action:"set"` 时列出 `must_deliver[]`——"这次请求要算完成，必须存在哪些东西"。清单随契约写进 transcript。

**记账**：`drift_anchor action:"coverage"` 为每项记判定——`complete` / `partial` / `missing` / `waived`。`partial`/`missing` **没有人类授权就是方向变更**，需要 `drift_report` 拿到明确同意。

**闸门**：turn 即将关闭时只要还有未完成项，就用 `agent.steer()` 强制再走一步，给三个出口：

1. 现在做完，用 `coverage` 记 `complete` 并给证据；
2. 用 `drift_report`（reason `incomplete-delivery`）请用户接受部分交付；
3. 老实停下报告未完成——**不许把部分交付描述成完成，也不许把剩余工作单方面改名成"后续"**。

### 推迟措辞检测：默认关闭（测量结论，不是保守选择）

曾经有一层会扫描 agent 自己的输出，命中中英文的缩减/推迟措辞时记录下来。**它现在默认关闭**，原因是三次真实运行给出了三次同类误报：

| 次数 | 触发文本 | 性质 |
|---|---|---|
| 1 | 守卫自己的政策段（"shipping a labelled subset…"） | 自我误报 |
| 2 | README 被引用 | 引用误报 |
| 3 | 守卫开场语里的 `partial delivery` 被我引用 | 讨论误报 |

我为此加过一次规则（要求**同句出现工作动词**），真实文本立刻换了个方式绕过去。

**结论**：prose 层面的意图信号没有判别力——因为语料里充满了**正在讨论被检测之物**的文本。这与 `dsh-trajectory-anchor` 对自己统计通道测出的结论同形（precision 6.2%，低于 20% 的随机基线）。

它**只记录、从不执法**，所以关掉它只减少噪声、不损失任何能力。代码保留、`reportDeferrals: true` 可重新开启，供任何人用自己的语料重测。

对比之下：**账本是事实**（清单是 agent 声明的、判定是 agent 给的、闸门只核对有没有如实记账），真实运行零问题。**把猜测关掉，把事实留下**，是这一层唯一诚实的取舍。

## 完整性的能力边界（不假装）

- 只核对**声明过**的 `must_deliver`。不声明就没账可查（此时 `set` 的结果会明确提醒）。
- **无法验证 `complete` 是否为真**。要求附 `evidence` 只是把声称与证据绑定，不是验证。
- 判定 `partial`/`missing` 时**总是**记入账本（那是 agent 自己的声明，藏起来只会让账本说谎），但**不会**因此授权缩水。

## 方向变更协议

九类：`scope-expansion` · `constraint-conflict` · `behavior-change` · `architecture-shift` · `data-model-change` · `compatibility-change` · `assumption-invalidated` · `user-direction-change` · `incomplete-delivery`

两个护栏（借自 `dsh-requirements-alignment`）：

- **默认选项兜底**：无论模型提供什么选项，"批准改方向"和"留在当前范围"始终被补上（按标签去重）。防止"留在原范围"的意图被裹进模型改写的标签里、被错记成"修改方向"。
- **答案映射严格化**：自由文本 → `revise`（note 为用户原话）；默认选项 → 按精确标签 `approve`/`reject`；选中的模型选项 → `revise`；**没有选择 / 多选 / 标签对不上 → 抛错，不写任何状态**。静默把决定错记成"拒绝"会污染基线，比报错难查得多。

## 姿态状态机

`unknown` · `aligned` · `drift-pending` · **`baseline-update-pending`**

最后一个是关键：**用户批准了新方向，但新契约还没提交**。这个窗口里会话若被打断，绝不能折成 `aligned`——否则是拿**过期契约**当有效。

## 跨会话经验（教训）

**让「同一种错只犯一次」成为机制，而不是靠记性。**

会话结束时学到的东西会随会话消失，所以同一个错误一直**有机会再犯**。这一节让它活过产生它的那次会话。

### 用法

- **`drift_lesson`** —— 我主动记录：症状、该怎么做、以及**什么情况该把它翻出来**
- **`drift_lessons`** —— 只读查看全部教训，含哪些还有效、哪些已被取代
- **开头注入** —— 全部有效教训在**会话开始时注入一次**，此后**字节不变**

### 三个定死的设计决定

**① 只增不改。** 教训永不重写、永不删除。撤回是**追加一条取代它的新教训**，并在**旧记录**上写 `supersededBy`。原因：注入块位于每个请求的**最前面**，改写旧条目会让所有会话的提示词前缀字节移动，而**前缀缓存从第一个不同的 token 起全部失效**（这一条我们刚在上下文用量那里踩过）。

**② 触发条件是闭合枚举，只有四个。** 我只能在 `bulk-replace` / `before-editing-tests` / `long-turn` / `no-contract-yet` 里选，**不能自己造**。自由文本触发条件只能靠模糊判断匹配，而这个项目**已经实测过那类匹配**：语义相似度 precision 6.2%、低于随机。闭合枚举可以被机械判定，所以提醒**要么触发要么不触发**。

**③ 教训是「主张」，不是「事实」。** 这里没有任何东西验证一条教训是对的。**唯一存在的检查是人去读 `lessons.json`。** 这也是为什么「取代」是一等操作。

### 触发判定是机械的

测试文件必须**自称是测试**：`_spec`/`_test` 后缀、`.spec.`/`.test.` 中缀，或位于 `tests/` 下。

**"所有 `.mjs`" 会被明确排除**——那会在每次改源码时误报，而**不稳定触发的提醒会训练读者忽略提醒**，比没有提醒更糟。

### 边界（诚实清单）

1. **我不会自动扫会话日志找教训。** 记录这一步靠自觉（我或你调用 `drift_lesson`）。**代价是**：犯了错却没记录，它就学不到。这是刻意的——扫日志要用启发式判断"什么算教训"，而上面那个 6.2% 就是那类方法的实测结果。
2. **教训下一次会话才生效**，不是当次。注入块每会话只渲染一次并保持不变，所以当次记录不会改动正在使用的提示词。
3. **只提醒，不阻断。** 这是你选的。命中的教训最多**每个会话提醒一次**——重复提醒就是噪声。
4. **`lessons.json` 损坏不会拖垮插件**：会话按"没有教训"运行，工具在写入时才报真实错误。

## 自我改进（RSI）与它的硬边界

插件可以**读取真实会话日志、发现摩擦、提出阈值改动、验证、并自行提交**。但它**改不动自己的机制**——这不是保守，是因为「自我改进」和「静默改写目标」在机制上是同一个动作，区别只在于**谁能改、改什么、留不留痕**。

### 守卫会**强制我记录**，而不是等我想起来

记录靠自觉，就等于没有——**这正是这个功能要治的病**。所以守卫**自己数**这一轮有没有在打转：

| 机械信号 | 判定方式 |
|---|---|
| `bulk-replace` | **同一个调用逐字重复** ≥2 次 |
| `before-editing-tests` | **同一个文件**本轮被写 ≥3 次 |
| `long-turn` | 本轮 ≥20 步 |

**三个都只是计数**，不是判断"这次调用好不好"——被动观察者**无法知道**一次失败是"有教益"还是"单纯打错字"。所以守卫**只陈述它数到了什么**，正文由我来写：

> `Observed: - long-turn: ...`
> `The guard cannot tell whether what happened was instructive or just a typo, so it does not guess at the content. You are the only one who knows.`
> `If the friction was incidental and taught nothing, say so and close.`

**三个约束**：本轮**最多问一次**（靠 `lessonRequested` 标记，而不是 steer 计数——后者每次调用都从原始条目重算，单靠它会在上限之内又问第二次）；**已记录就不再问**；**允许不记录**，说明理由即可收工。

**不阻断**是有意的：**会阻断的"请求"其实是戴着请求面具的闸门**，而这套机制存在的目的正是"让收工成为可能"。

## 停滞检测：把裸续轮词换成可执行指令

**这不是漂移，是空转**——而它**机械可测**。

**检测点是"跨轮"，不是"轮内"。** 这一点是**实测定的**，不是设计时拍的：扫 **194 个真实会话日志、2200 轮**：

| 形态 | 数量 |
|---|---|
| 以工具调用结束的轮 | **1737** |
| **以"无工具 + 短/空"结束的轮** | **278** |
| **连续无工具轮的最长序列** | **157** |
| 轮**内**出现 ≥2 条无工具消息的轮 | **1** |

**所以循环发生在轮与轮之间**：一轮空洞收尾 → 自动续轮 → 又一轮空洞收尾。我最初设计的"轮内检测"**只覆盖 1/2200 轮**，等于白做——**是测量把它纠正过来的。**

| 连续无工具收尾的轮数 | 守卫做什么 |
|---|---|
| **1** | **什么都不做**（正常的收尾回复） |
| **≥2** | 注入**可执行指令**：要么用工具做一件具体事，要么说清阻塞 |
| **≥4** | **升级给你**，然后停止 |

**任何一次工具调用都清零**，所以**正常收尾永远不会被触发**（正常收尾前面必有实际工作）。

**它为什么只发一次**：循环的燃料是自动续轮发来的裸"继续"。守卫**改不了那个提示词怎么生成**，但能让下一轮续轮**带着一条可执行要求**到达，而不是又被回一句"继续。"。重复发同一句话只会变成循环的一部分——**所以第 4 轮起改为报告，而不是继续念。**

**它治不了什么（写死在升级文案里）**：**没有重采样、没有 logit 处理、没有停止序列控制**。如果回复**看起来像胡话而不是像停滞**，那是**采样问题，不是漂移问题**——**守卫不会假装自己能修采样器。**


#### 触发条件是分开的两件事

这两个**不是同一件事**，早期版本把它们混成一个，**真实使用一次就暴露了**：

| 触发条件 | 判定的是 | 依据 |
|---|---|---|
| `bulk-replace` | **这次调用本身**是否在批量改写 | 调用名含 sed/awk/replace/bulk，或命令里有 `sed -i`、`.replaceAll(` |
| `repeated-call` | **历史**里同一调用是否又来了 | 同一调用逐字出现 ≥2 次 |

混在一起的后果：**"我把同一个查找命令跑了两遍"被报成 `bulk-replace`**，于是记录的 trigger 名**与真实发生的事不符**——而 trigger 名正是未来检索这条教训的钥匙，名字错了就等于没记。

## 教训库放在哪里

**默认落在 DSH 进程的工作目录**，实践中就是**该 profile 的目录**：

```
<DSH profile 目录>/lessons.json        例：C:\Users\cheng\.dsh\profiles\desktop\lessons.json
```

**这不是仓库的一部分**（它是使用者的数据，不是插件代码），所以**不会也不该被提交**。

**要当心的坑**：默认值是相对路径 `'lessons.json'`，所以**换一个目录跑 DSH，就会读到另一个（空的）教训库**，看起来像"教训全丢了"——而旧库其实还在原处。排查时先按 profile 目录找，别急着断言功能坏了。

**要固定位置**就显式配绝对路径：

```json
{ "lessonsFile": "C:/Users/you/dsh-lessons.json" }
```

### 能力

| 部分 | 实现 |
|---|---|
| **信号挖掘** `rsi.mjs` | 读 `~/.dsh/sessions` 的**真实日志**，数出可机器判定的摩擦：steer 次数、steer 循环、检查点次数、无契约时的追问、伪造引文、升级次数、重复未完成项。**全是子串事实，不做语义打分**——同一输入两次跑必须一致 |
| **提案** | 每条规则都带触发它的证据，且只在边界内动 |
| **验证** | 在**临时副本**里跑 `check.mjs` + `teeth.mjs`。要求**正向全绿证据**（出现 `all checks passed` 且无失败标记），**不接受只看退出码**——退出码在本项目已经歧义过一次 |
| **自提交** | 每次自改**单独 commit**，message 里带观察到的证据、信号来源、以及变异抓取数 |
| **宪法冻结** `core.json` | 8 个机制函数体各一个 SHA-256，**加上策略区之外整个文件的哈希** |
| **白名单** | 只有被标记的策略区内的**纯字面量**、且**在白名单键内**才能改 |

真实日志是 **zstd 多帧压缩**（`session.v4.jsonl.zstd`，一个会话可含数千帧）。**只解第一帧会得到 196 字符的会话头**，于是所有会话看起来都是空的、循环报告"无摩擦"——**那是最危险的答案，因为它读起来像一份健康证明**。挖掘器逐帧解压。

### 什么是「机制」（不可自改）

`citedBasis`（引用授权）、`autoResolution`（三道闸门判定）、`derivePosture`、`unfinishedItems`（账本）、`renderContract`、`renderBaseline`、`validateDriftArgs`、`validateAnchorArgs`。

**还有更重要的：`check.mjs`、`teeth.mjs`、`rsi.spec.mjs` 和 `rsi.mjs` 自己都不在白名单内。** 如果学习器能改写「什么算改进」，它就是**在给自己发合格证**。这条限制是有意的，不是遗漏。

### 硬边界（诚实清单）

1. **没有「这次改动是否更好」的可信信号。** `teeth.mjs` 回答的是"这个变异有没有被抓到"，那是客观的；**没有人回答"改动是否让插件更好"**。这个循环优化的是**可测量的摩擦**，而摩擦下降也可能是因为闸门变松了——**这正是三道防线存在的唯一理由**。
2. **`check.mjs` 与 `rsi.spec.mjs` 不合并。** 变异验证会故意改写 `index.js`，而 RSI 规格断言 `index.js` 与宪法一致——两者**本质不兼容**。用 `test-all.mjs` 一次跑完。
3. **策略区只有数字和布尔。** 一个表达式可以藏在阈值形状后面，所以在**任何测试运行之前**就被拒绝。

### 用法

```powershell
node rsi.mjs              # 干跑：报告会改什么、为什么，不写盘
node rsi.mjs --apply      # 验证通过则写入、单独提交（推送仍需你执行）
node rsi.mjs --init       # 人工审查机制改动后，重新固化宪法基线
node test-all.mjs         # 跑全部套件
```

**每个自改 commit 都带着触发它的证据，也都可以 `git revert`。**

## 上下文用量（按需查询，不注入提示词）

用 **`drift_context_usage`** 工具读取当前上下文占用。**这一行不会被自动注入提示词**，这是刻意的。

```json
{ "available": true, "usedTokens": 132400, "contextWindow": 1000000,
  "remainingTokens": 867600, "percent": 13, "projected": true,
  "summary": "132.4k / 1.00M tokens used (13%)", "note": "..." }
```

### 为什么不做成自动注入

**因为它会破坏 KV 前缀缓存。** 用量数字放在 `systemPrompt.context()` 里就位于**整个请求的最前面**，而前缀缓存从第一个不同的 token 起全部失效——于是每次数字变化都会让缓存的提示词前缀作废，整段前缀要重新处理。

而这恰好是**最坏的情况**：数字在低占用时基本不动（代价为零），但**越接近满、它变得越频繁**——正好是最不能承受缓存重建的时候。DSH 自己就在追踪这件事（`pressureTokens = inputTokens + cacheReadTokens + cacheWriteTokens`，缓存读写分开计价），所以代价是可见的真实成本。

**信息价值和缓存代价在这里是矛盾的。** 我们选了保缓存：提示词逐字节稳定，需要时问一句就行。

### 数字的来源与诚实边界

取自 **DSH 自己的 token-meter**（`contextPressure`），优先 `projectedTokens`（token-meter 定义的"下一次请求会花多少"），回退 `pressureTokens`。**本插件不自己估算**——第二个口径算出来的数字会和你界面上看到的不一致，而**错的占用率看起来和对的没有区别**。

**没有可信读数时 `available: false` 并给出原因**，绝不给一个看起来像测量值的数字：

| 情况 | `why` |
|---|---|
| 未注册 token-meter | `no token-meter projection is registered in this composition` |
| meter 尚未报告 | `the token meter has not reported a prompt size yet` |
| 有计数但窗口未知 | `the token meter has counted tokens but the model context window is not known yet` |

输出是**恒定形状的扁平对象**（registry 要求每个声明的字段都必填），所以 `available: false` 时那些 `0` 是**哨兵值**，由 `available` 消歧——不是声称的测量结果。

`note` 字段携带契约风险提示：窗口被压缩后**原始请求可能检索不到**，如果剩余工作放不下应当**明说放不下什么**，而不是悄悄少做。
## 全自动模式与三道机械闸门

用户可以选择**不被偏移决策打断**。这条路解决了"每次都来问我"的烦扰，但代价必须写清：

> **全自动在机制上放弃了事前闸门。** 自动化本身就是"无人批准的目标改写"，所以这道防线退到了**机械可验证**的三道闸门——它们防的是**结构性滑移**（无授权扩张、范围缩水、累积膨胀），**不是语义变质**。语义漂移分数这类方案我们测过，没有判别力（见上文推迟检测一节）。

关键取舍：**"这还算同一个目标吗"是语义判断，不可靠；"这次变更有没有出处"是机械检查，可靠。** 所以自动裁决只在后者成立时放行。

| 闸门 | 机制 | 失败时 |
|---|---|---|
| **A 引用授权** | `drift_report` 必须给出**原始请求的逐字引文**（`basis`），机器校验该子串**确实存在于你的原话里** | 引不出原文 → 升级为提问。**偏移需要伪造引文，而伪造引文是可见的**，不是悄悄发生 |
| **B 范围只增不减** | 新的 `must_deliver` 相对上一版**删除**任何一项（或用 `drops_deliverables` 指名）→ 判定为缩水 | 立即升级。`incomplete-delivery` 与 `constraint-conflict` **永不自动批准**——用户从没要求少做 |
| **C 累积漂移预算** | `新增项数 / 当前契约项数` 累加为比值，默认上限 **0.5** | 超限后**后续所有自动裁决全部升级**。用**比值**而非次数，是为了让大契约吸收更多小幅新增，**"再来一项"无法无限累积** |

**可恢复性**：每次自动裁决都落账，并在每次请求的契约渲染里列出（`auto: N quote(s); ratio X%`）——你能看到它自己决定过什么。**但事后可见 ≠ 事前可控**，这是选全自动必须接受的代价。

**关闭方式**：`autoDrift: false`，之后每次偏移都会来问你。

## 为什么"跑偏"可能有两种成因（相位敏感性）

这一节记录一个**改变了归因**的外部发现，以及它对这套设计的含义。

字节 Seed 的论文 [*Periodic Weak Spots: Phase Sensitivity from Chunked KV-Cache Compression*](https://arxiv.org/abs/2609.36322)（arXiv:2609.36322）指出：分块 KV 缓存压缩按固定步幅把连续 token 压成更少的条目，因而引入一个新的位置坐标——**相位**（token 相对压缩窗口边界的位置）。使用这种压缩的模型存在**系统性不对称**：同一信息在某个相位容易检索，在另一个相位很难。在大型开放权重模型上，长上下文检索准确率**跨相位最多相差 40 个百分点**。作者从零预训练复现了该现象，并用因果干预做了机制分析。

**它带来的区分**（这一点比论文的数字更重要）：

| 成因 | 机制 | 应对 |
|---|---|---|
| **检索不到** | 目标在上下文里的相位落进弱区，模型真的看不见 | 改变信息的**注入位置** |
| **检索到却违背** | 模型看见了目标，选择了别的事 | 机制**强制拦下** |

两者**表现完全一样**（都像"回不到正轨"），但应对方式不同。本项目此前把所有观察都归因于第二种，这个归因**很可能不完整**。

**哪些机制免疫、哪些不免疫：**

- **账本与闸门免疫。** 它们依赖 agent **当场声明的清单和判定**——那是刚生成的内容，不从长上下文深处捞回来，因此不受相位影响。这是"用声明+记账代替检索"这个设计事后才被解释清楚的一条附带好处。
- **固定位置基线与检查点不免疫。** 基线就在上下文靠前的固定位置；检查点在"第 N 步"触发也是一个与相位无关的任意点，所以它自己那条消息同样可能落进弱区。

**关于"每次请求重新陈述契约可能缓解相位弱区"——这是假设，不是结论。**
论文**没有**研究周期性重注入，也没给出任何缓解方案；它唯一的处方是"评估这类模型必须跨相位测量"。重注入是否真的起到作用，取决于本推理栈的压缩步幅与提示词长度（两者都不在本插件的控制内），**未被验证**。

**一个可用的诊断动作**：当契约明明注入了、模型却没有遵守时，先让它**当场复述目标**。能复述却仍在做别的 → 行为问题；复述不出来 → 更可能是检索问题。这比再加一层拦截机制便宜，也比直接断言"它在偷懒"准确。

## 子 agent

子 agent 没有人类应答者，所以**不能**提交契约、**不能**发起方向变更提问。它应在最终报告里放一个 **"Requirement drift candidate"** 块（原因、当前契约、需要的变更、需要父 agent 替它问什么）。父 agent 拥有用户交互权。

> 这修掉了原先的真窟窿：子 agent 无法设契约，导致预算闸门和 steer 闸门对它**静默失效**。

## 两个必须知道的坑（都真的踩过）

**1. `tool/call` 事件里的 `arguments` 是 JSON 字符串，不是对象。**
`session-format-*` 把 `arguments` 列为字符串字段；解析成对象是 dispatch 层之后的事。折叠日志时**必须自己 `JSON.parse`**。第一版按对象读，于是契约**从来没进过投影**，跨 turn 就消失。症状极具迷惑性：同一个 turn 内一切正常。

**2. 改 `index.js` 之后，`plugin_manager` 的禁用/启用不会重新 import 模块。**
`set_plugin` 只是卸载/重挂那一行，ESM 缓存里的旧模块被复用（实测：改了 schema 后 `cordis_inspect_query` 返回的仍是旧 schema；在 `apply()` 里写标记文件，toggle 后文件不出现）。**改代码后必须重启 DSH 进程**才会生效。

## 自检与变异验证

```powershell
node check.mjs    # 87 项，无需运行中的 Harness
node teeth.mjs    # 变异验证：把真实回归注入源码，确认测试会变红，然后恢复
```

`check.mjs` 覆盖：配置校验、投影折叠（基线/契约/覆盖/方向变更/姿态/持久化往返）、两道闸门、完整性账本四种判定、答案映射全部路径、默认选项兜底、中英文推迟措辞与假阳性、两个工具的参数与输出 schema 是否落在 registry 强制的 JSON Schema 子集内。

`teeth.mjs` 是本项目的**纪律工具**：注入 6 个真实回归，跑 `check.mjs`，报告几项变红，然后恢复源码。当前结果：

| 注入的回归 | 变红 |
|---|---|
| 新请求保留旧契约（不做重置） | 1 |
| 预算改用全会话步数 | 1 |
| 检查点忽略已清空的账本（"做完还催账"） | 2 |
| 推迟检测去掉工作动词要求 | 1 |
| 读取非 model 来源的 assistant 记录 | 1 |
| checkpoint 内存改用契约键 | **0（抓不到）** |

**最后一条如实说明**：该 keying 在当前实现下**行为等价**——新请求时契约本就被置 null，代码走"无契约"分支，两种键法结果相同。它在语义上更正确（账本属于请求，不属于契约），但**没有可观测差异可供测试捕获**。我尝试构造区分场景（同一请求内修订契约后再次超支）失败，因为该路径由 `atStep` 守卫主导，不由这个键主导。这不是"以后补测试"能解决的，是等价变换。

**第 3 条是本次修复钉下的**：`budgetCheckpoint` 原先只看预算、不看账本，于是**已经逐项完成并举证的请求仍会在每步被催"该盘账了"**——纯粹噪声，而噪声会训练读者忽略守卫。`turn-stopping` 那条闸门一直有这个守卫，消息路径漏了。
